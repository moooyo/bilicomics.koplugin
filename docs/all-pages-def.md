# Catalog and download handoff audit

The reference is the complete external Scribe handoff README and its D1–D4 and F1–F4 HTML artboards. The source uses a 930 × 1240 dp reference and native KOReader widgets. Screenshots are produced by the official KOReader v2026.07.1 emulator at 1860 × 2480, 480 × 640, 600 × 800 and 960 × 720 in Chinese and English. All records and covers are synthetic; every native process has its own profile and an isolated network namespace without routes.

The audit does not use historical assertion counts as evidence of visual fidelity. It captures each named state, reads native painted geometry, checks the current-chapter marker in the framebuffer, and exercises relevant callbacks. Outputs remain outside the repository. Browser access to the local prototype was unavailable, so geometry requirements come from the actual HTML and README source; this is not a browser raster comparison.

Data-dependent content is not fabricated to match example values. Estimate bytes come only from declared local totals or observed image sizes. Unknown sizes remain unknown. Retained versions report their own revision's bytes, and incomplete comic byte totals are not presented as complete totals. The normal current-copy recovery card retains its truthful warning that missing images may be fetched; the saved-only warning is reserved for a retained copy. A new-version card explicitly preserves the old copy's saved images and reading position.

Every generated multi-page dialog is painted in both directions, then returns to its first page before subsequent actions. This exposed a shared native-widget ownership bug in full-page replacement: closing the previous shell freed body widgets reused by later pages. The shared flow builder now detaches the borrowed body before replacement, and the catalog/download acceptance verifies that backward painting and actions remain usable. The historical download-recovery and version-replacement behavior suites retain their assertions; their strict fake controllers gained only the new read-only estimation method with an unknown result.

The focused executable is `spec/ui/all_pages_def_spec.lua`, with `spec/ui/run_all_pages_def.py`. Purchase E1–E5 and its additional evidence-sensitive states are covered separately in `docs/all-pages-purchase.md` and the root all-pages acceptance run. Font metrics vary between the browser prototype and the bundled native font; the checks distinguish fixed geometry from data-dependent text wrapping rather than claiming exact browser pixels.

The final frozen-source matrix passed all eight size/language combinations with 3,703 assertions and 572 screenshots. Both the before/after UI source hashes and all required dimensions matched. The current receipt is [all-pages-def-verification.json](../spec/ui/all-pages-def-verification.json); it identifies the external `all-pages-final-def` case reports and captures. The [complete-page coverage receipt](../spec/ui/all-pages-acceptance.json) verifies the current hashes and every required D/F page at all eight combinations.

The separate historical semantic regressions passed at Scribe and 480 × 640: download recovery has 393 assertions per size; version replacement has 400 assertions per size. These results supplement the per-artboard geometry and framebuffer evidence, not replace it.
