# Internal Development Contracts

These contracts coordinate the first implementation. Public service calls return `value, error`, with errors shaped as `{kind, message, retryable, code?}`. Storage writes may raise errors; transaction boundaries must roll back. Async controller callbacks receive `(value, error)`. Identifiers are normalized to strings; episode order remains numeric and may be fractional.

## Data

- Comic: `{id, title, authors?, cover_url?, latest_episode_id?, latest_order?, favorite?, finished?, updated_at?, extra?}`.
- Episode: `{id, comic_id, order, title, short_title?, access, expires_at?, pay_gold?, read?, extra?}`. Access is `free`, `owned`, `temporary`, `locked`, `unavailable`, or `unknown`.
- Descriptor: `{schema_version=1, account_key, comic_id, episode_id, revision, pages={{id,index,width,height},...}}`. No credentials, URLs, mutable availability or titles are stored here.
- Page: `{key, episode_id, revision, index, id, state, path?, width,height, format?, content_generation,geometry_generation,checksum?,extra?}`. `key` is `episode_id .. '/' .. revision .. '/' .. index`; state is `missing`, `ready`, or `failed`.
- Job: `{id, kind, state, episode_id?, comic_id?, revision?, page_index?, priority?, payload?, completed?, total?, error?, updated_at?}`. States: `queued`, `running`, `paused`, `complete`, `failed`, `canceled`.
- Purchase intent: `{id,state,episode_ids,comic_id,quote,before_access,expected_access,purpose,created_at,updated_at,error?}`.

## Storage (`bilicomics/storage/`)

`Store.open({root, account_key, wal?}) -> store`, `close()`, `transaction(fn)`.

Methods: `upsertComic(record)`, `getComic(id)`, `listComics(kind, opts?)`; `upsertEpisodes(comic_id, records)`, `getEpisode(id)`, `listEpisodes(comic_id)`; `putPage(record)`, `getPage(key)`, `listPages(episode_id, revision)`, `updatePage(key, patch)`; `putJob(record)`, `getJob(id)`, `listJobs(states?)`; `putPurchase(record)`, `getPurchase(id)`, `listPurchases(states?)`; `putAnchor(episode_id, revision, record)`, `getAnchor(episode_id, revision)`; `getSetting(key, default)`, `putSetting(key, value)`.

`PageStore.new({root, account_key, store})`; `ensureDescriptor(descriptor) -> path`; `readDescriptor(path)`; `getPage(episode_id,revision,index)`; `commitPage(context, result) -> page`; `pinEpisode(episode_id,revision,pinned)`; `isComplete(episode_id,revision)`; `reconcile()`; `clearAutomaticCache()`; `getSummary()`. Context includes descriptor identifiers, page index, captured `expected_content_generation`, and optional `expected_source_generation` and `expected_checksum`; result supplies an already verified `temporary_path`, format, oriented width/height, SHA-256 checksum, and source geometry. Main-process commit owns final rename and database updates.

Page history in `extra` retains `last_committed_checksum` and `content_history_version=1` after eviction, removal or corruption. Only genuinely new descriptors initialize known never-committed history; repairing old records does not infer it. `extra.source_generation` versions mutable acquisition paths independently of descriptor identity and content generations. `extra.expected_source_checksum` binds subsequent reacquisition of a historically committed page.

`storage/source_refresh.lua` exports `capture(pages,episode_id,revision)`, `validateIndex(basis,index)` and `adopt(pages,basis,index,proofs)`. Capture returns a sealed, single-use basis bound to that PageStore. Adoption requires identical ordered topology, proof of every historical digest, unchanged ready-reference identities and a transactional comparison with the captured descriptor, rows, anchors and job generations. It updates mutable source fields only; descriptor bytes, page IDs and existing ready files retain their identities. Unknown history and unproved precise positions are errors, not permission to remap old content. Capture/adoption inspect metadata; hashing occurs in workers. Transient `source_refresh_locks` protect automatic cache separately from permanent pins and are released on every terminal coordinator path.

`root` is the already resolved account directory. SQLite handles may only be used by their creating process. Page commit and activation own the outer transaction boundary. `setActiveEpisode(episode_id,revision,true)` adds its reference only after the write commits; the matching `false` releases it even if the database is unavailable.

Call full `reconcile()` only before workers start. Runtime retry/resume uses `recoverPendingCommits() -> {recovered,recovered_pages,discarded,remaining,errors}`, which only handles journal-owned files. Notify readers for every `recovered_pages` item after recovery returns. An unresolved journal blocks new acquisition for its episode/revision, without blocking other chapters or deleting their workers' temporary files.

## Protocol (`bilicomics/protocol/`)

`Client.new({session,transport,crypto?,clock?})`. All methods are synchronous **worker-side** operations and never automatically retry purchases.

`validateSession()`, `listFavorites(opts)`, `listHistory(opts)`, `search(query,opts)`, `comicDetail(comic_id)`, `imageIndex(episode_id)`, `imageTokens(paths,opts?)`, `downloadImage(token,path,opts?)`, `wallet()`, `purchaseInfo(episode_id,scope?)`, `discountList`, `discountPrice`, `freeGoldCardInfo(comic_id,episode_id,scope)`, `buyEpisode(payload)`, `setFavorite(comic_id,boolean)`.

Normalizers must preserve relevant raw fields in `extra`. Missing current-protocol capabilities return an explicit capability error; they never pretend a fixture or historical request succeeded. The crypto adapter has an explicit capability report and isolated signing/response/image methods.

Session module handles cookie import, stable identity and private file persistence. Logs and ordinary data must omit cookies, tokens and private keys.

On Android, account credentials use the app-private `android.dir` returned by the platform's `Context.getFilesDir()` integration. Shared DataStorage mode bits must not be treated as a guarantee of private credential storage. The controller's session storage layer resolves this exception while leaving ordinary account state and immutable descriptor paths unchanged. Linux keeps the existing account-directory session location.

## Purchase (`bilicomics/purchase/`)

Service receives `{store,account_key,client?,clock?,id_factory?}`. Its synchronous `quote`, `submit`, and `reconcile` conveniences must not run with a real network client on the UI thread. The application uses main-process `buildQuote`, `prepareSubmission`, `completeSubmission`, and `completeReconciliation`, with request data acquired by separate workers. `recover()` runs only after any previous workers have stopped; `listPending()` is local.

Confirmable quotes carry the single chapter or original server-supported range, intended episode IDs, method/assets, amount, fingerprint and before/expected access. Durable states distinguish `submitting`, `accepted`, `outcome_unknown`, `access_confirmed`, `rejected`. Store before transmission, never automatically resubmit, and do not regress an accepted transaction on later refresh errors. Standard-currency batch quotes require the typed [ordinal range proof](ordinal-range-contract.md), independently reconstructed by Quote from the original catalog and both quote responses. Its `server_confirmed_ids=false` marks intended members rather than a server reservation. Fresh confirmation must reproduce the same fingerprint.

The integrated quote adapter provides `Selection.normalize(scope,payment)`, `Selection.requestScope(scope)`, `quote_fetch.run(client,request)` and `Candidate.describe(info,episode,selection,context)`. The worker and synchronous Service use the same collector; `buildQuote` accepts its context as a sixth argument and forwards the full original detail. Context binds comic, episode and copied selection. Basic and range responses retain their independent meanings and original offer-price association. Only server response fields supply monetary/eligibility observations; user selection cannot supply them. Extra-discount and unproved batch choices return `submittable=false` advisory objects with no payload, exact episode set or confirmation fingerprint. Service, Controller and UI each exclude these objects from submission. See [the implementation and verification limits](quote-selection-implementation.md).

`range_outcome_pending` persists ordinal transaction uncertainty independently of confirmed reading access. A held range blocks further same-comic purchases even when their old intended ID sets are disjoint. Ownership reconciliation can allow the original read/download continuation without clearing that transaction hold. A conclusive submission response may clear it. The `purchase.range_pending_ids` setting is updated in the same journal transaction; `recover()` rebuilds it once, and `listPending()` uses filtered states plus indexed held IDs instead of scanning completed history repeatedly.

## Jobs (`bilicomics/jobs/`)

`Runner.new({ui?,worker?,clock?})` owns real forked workers, framed IPC, child reaping and standby holds. `submit(request,options,callback)`, `promote(id,priority)`, `cancel(id)`, `suspend()`, `resume()`, and `close()` are main-process operations. Callbacks run after the child exits. The default pool admits two workers and one image task; worker processes never use inherited SQLite handles.

Only allowlisted read operations can retry classified network/timeouts or HTTP 429/5xx responses, at most three attempts with one- and two-second backoff. The delay owns no worker or standby hold. Generic HTTP 403 and authentication failures never refresh tokens blindly. `purchase_submit` and `set_favorite` are unconditionally nonpreemptible and cannot enter automatic retry. Explicit shutdown may terminate a purchase, leaving durable uncertainty for reconciliation; a favorite changes locally only after a consistent server acknowledgment.

`set_favorite` takes `{comic_id, favorite}` and returns `{accepted=true,comic_id,favorite}` only after the protocol confirms success. It is not reachable through the generic read-only `client` method allowlist. `diagnostics` constructs a separate client without a session and with a transport that rejects every network request. Its result contains only typed local versions, platform and boolean capability fields, and explicitly says that networking was not checked. The controller uses a separate local runner so this operation does not resume or wait on a suspended network queue.

`DownloadService` deduplicates page requests by episode/revision/index and tracks reader/job owners separately. It captures content, source and service generations before starting work. Both successful and failed completions, including authentication errors, must match their captured page epochs. Complete downloads are pinned; complete automatic cache alone is not a retained-download badge. Closing a reader removes its ownership while explicit downloads remain process-scoped.

`refreshSources(job_id,fetch_index,callback,check_positions)` explicitly pauses a retained partial download, captures its basis and serially verifies historical pages before atomic adoption. `isRefreshingSources(job_id)` and `cancelSourceRefresh(job_id)` expose lifecycle state. The Controller checks stored native reading positions, fetches fresh entitlement/index data, and pins the retained download before resuming after successful adoption. No generic HTTP 400/403 automatically invokes refresh. Cancel, suspend and account changes retire in-flight proofs; startup clears an interrupted marker without replaying it. Terminal storage or resume errors still deliver one callback and never claim unperformed resumption.

Worker `source_index` requires the exact comic/episode and fresh offline eligibility before index retrieval. `verify_source_page` requires an expected SHA-256, a contained temporary file, and an optional ready-reference path/root/identity; it hashes the reference in the child, validates candidate bytes, and rechecks the reference after acquisition. Replaying a preempted worker can reset its own regular partial file but cannot alias a reference. Runner suspension preserves an existing cancellation/timeout instead of replacing it with preemption. See [the recovery contract and evidence](partial-download-recovery.md) for the separate same-snapshot and independent-version paths.

Explicit independent replacement uses `storage/version_replacement.capture(pages,job_id)` and `publish(pages,basis,index)`. It requires a paused retained partial download and a fresh confirmed-readable index. A new local revision is allocated independently of server revision/path equality. Publication atomically creates new descriptor/page records, a pinned paused job, the current-revision selection and old-job retirement. Every retained job referencing the old snapshot is marked `payload.replaced_by`; the new job records `payload.replaces_job_id`. Publication pins both versions, including an otherwise unpinned legacy snapshot, honoring the confirmation's promise to retain old data until explicit removal. Old files and per-version anchors remain owned by visible retained-version entries. No page, progress or document identity is migrated into the new snapshot. Orphan descriptor files from a failed transaction are excluded from database selection and are never reused as a later snapshot.

The process-scoped `jobs/version_replacement` flow exposes `replaceVersion`, `isReplacingVersion` and `cancelVersionReplacement` through DownloadService. It owns only a fresh read-only index task and stores a bounded `payload.version_replacement` marker. A temporary `PageStore.version_replacement_locks` lease protects old cached bytes while preparation is pending. Failure/cancellation releases it without changing the old permanent pin; successful publication establishes both permanent pins before lease release. Source refresh and independent replacement are mutually exclusive. Cancellation, suspension and account closure terminate the operation; startup clears an interrupted marker without automatically dispatching another request. Once publication succeeds, Controller explicitly resumes the new job. A subsequent resume failure returns the published value with an error so callers do not mistake an already-created snapshot for a rolled-back attempt.

An assigned `job.revision` is authoritative on resume. DownloadService reads that descriptor directly instead of substituting the catalog's current version. Retired snapshots permit cached-page reads only, including native direct reopening; missing pages cannot initiate acquisition. Removing a retained snapshot marks every job referencing that episode/revision removed, matching the revision-scoped pin and image ownership.

`storage_budget.lua` queries a fresh native `statvfs` structure and uses `f_bavail * f_frsize`. Check free headroom before queueing missing images and again inside the worker before acquisition. Low space may evict eligible automatic pages and pauses explicit downloads; pins, active chapters and pending commits remain protected. Cache hits and journal recovery do not require spare download capacity. This preflight is not a filesystem reservation against unrelated applications.

`image_policy.lua` sets the conservative cover source limit to 4,000,000 pixels. Cover acquisition checks it before returning a usable result, and the UI checks a cached file's bounded header before constructing an ImageWidget. Oversized covers use the existing title placeholder; chapter images keep the reader's separate format/device policy.

## Reader (`bilicomics/reader/`)

`document.lua` exports the native provider. It accepts `services` when explicitly constructed and has `setServicesResolver(fn)` for registry-opened descriptors. Resolver receives `account_key` and returns `{store,pages,requestPage?,onReaderEvent?,settings?,isCurrent,authorizeDescriptor}`. Production descriptor identity and access authorization is mandatory, including before cached rendering.

`requestPage(descriptor,index,{prefetch?,reader_generation?})` is a nonblocking hint. Reader rendering only reads local state/files. Persistent page/content generations come from the store. Native integrations are instance-scoped and cleaned up on close.

`Bootstrap.register()` must execute before KOReader chooses its startup document, using the managed `2-bilicomics-provider.lua` user patch. Normal plugin loading is too late for direct cold-start reopening. Where startup patches are unavailable, `prepareFallback()` runs on reader readiness and settings flush, clearing only an owned comic `lastfile` while preserving history and anchors.

`Defaults.capture(reader,config,true)` runs through the production plugin's `DocSettingsLoad` hook before native setting migration. `Defaults.apply` preserves saved per-document values and valid anchors; only new chapters receive global BiliComics `reading_mode` (`auto/page/strip`) and `reading_direction` (`ltr/rtl`). Auto mode uses the first image's aspect ratio. Native reading-order and zoom/pan APIs implement both gesture direction and within-page traversal without changing descriptor order. `Defaults.save` persists standard scroll and writing-direction keys that this provider's absent ReaderConfig would otherwise not save.

## Native business UI (`bilicomics/ui/`)

Export `Screens.new({controller})` and `showLibrary(kind?)`, `showComic(comic_id)`, `showDownloads()`, `showAccount()`, `showSearch()`, `close()`.

Controller contract: `getAccount()`, `getLibrary(kind,query?)`, `refreshLibrary(kind,cb)`, `search(query,cb)`, `getComic(id)`, `getEpisodes(id)`, `refreshComic(id,cb)`, `readEpisode(comic_id,episode_id,cb?)`, `downloadEpisodes(comic_id,episode_ids,cb?)`, `getDownloads()`, `pauseJob(id)`, `resumeJob(id)`, `cancelJob(id)`, `getWallet()`, `refreshWallet(cb)`, `importSession(text,cb)`, `quotePurchase(episode_id,scope,payment,cb)`, `purchase(quote,purpose,cb)`, `reconcilePurchase(intent_id,cb)`, `getSetting(key,default)`, `setSetting(key,value)`, `getStorageSummary()`, `clearAutomaticCache()`.

Purchase purpose is `read` or `download` and is validated before any quote or submission dispatch, then persisted with the intent. The older `purchase(quote,cb)` signature remains a read continuation. A locked chapter has an explicit single-chapter Buy then download entry; multi-selection never purchases implicitly. Pending results retain their original purpose. After durable access confirmation, an explicit continuation uses `intent.quote.episode_id` and can retry acquisition without another payment. Closing the result does not enqueue a continuation; the unlocked catalog remains available. Only `transaction_evidence="server_accepted"` supports payment-confirmed wording; entitlement-only evidence confirms chapter access.

Additional UI entries are `lookupComicID(input,cb)`, `resolveReadingEpisode(comic_id,cb)`, `setFavorite(comic_id,boolean,cb)`, and `getDiagnostics(cb)`. ID lookup is explicit and never reinterprets a numeric title search. Following cards expose both details and a direct reading action; completed chapters advance by canonical episode order, and locked targets open a quote rather than spending. Download selection uses offline eligibility independently of online readability.

Download recovery uses `refreshDownloadSources(job_id,callback)` and `cancelSourceRefresh(job_id)`. It requires explicit confirmation explaining comparison downloads and retained local progress. Verification progress replaces Resume with Cancel verification. Typed failures use fixed messages; raw source URLs, paths and protocol exceptions never appear. UI route/account generations retire obsolete callbacks.

Independent recovery uses `replaceDownloadVersion(job_id,callback)` and `cancelVersionReplacement(job_id)`. Confirmation explains a full new download, extra storage, a fresh reading position and preservation of the old version. Retired rows expose only exact-version reading and removal. `readDownload(job_id,callback)` opens that job's descriptor directly, without selecting the catalog's current revision. Chapter-wide progress for a replacement follows `episode.extra.source_replacement_revision`; an older snapshot keeps its own Store/native anchor without changing the newer snapshot's unread/finished state. `Store:putAnchor(...,{update_progress=false})` explicitly requests an anchor-only write, and the same isolation is automatic for older revisions of a replaced chapter.

Session import exposes `Import from file` in Account and in the existing masked paste dialog. `Screens:_importSessionFile()` uses KOReader's native `FileChooser`, starts at the configured KOReader home folder, and preserves ordinary directory navigation. A clicked file is the explicit import selection. The file list accepts `.txt`, `.json`, and `.cookies` extensions case-insensitively and ignores book reading-status filters. It does not discover or automatically import a particular filename. English message IDs and their Chinese translations are maintained in `l10n/bilicomics_zh_CN.lua`.

`ui/session_input.lua` exposes `accepts(path)` and `read(path) -> text, error`, with `max_bytes=131072`. Reading requires an absolute path to the selected regular file, rejects final symbolic links and nonregular objects, and checks the opened object's device/inode identity. A bounded read rejects files larger than 128 KiB, including growth during reading; empty or NUL-containing content is rejected. File errors contain only fixed `{kind="session_file",code}` categories, never input contents, cookies or paths. Supported UTF-8/BOM text, browser JSON and Netscape exports then use the unchanged `Controller:importSession(text,cb)` and existing Session parser, online identity validation and account-specific storage. The browser export is not the plugin-managed `session.dat` and is not automatically deleted.

The file-selection operation captures the screen epoch and account generation. Cancel, direct native picker closure, navigation and account changes retire unsubmitted selections. Obsolete or duplicate validation callbacks cannot reopen feedback or replace a newer import. Closing the status dialog suppresses late UI feedback; it does not undo a validation already explicitly dispatched. Success is shown only after the Controller reports validated, saved account state. No file-import change alters the Android app-private credential location or the existing Linux account-directory location.

Local getters must not perform network requests. UI errors must distinguish missing login, unsupported protocol capability, connectivity, locked content, and uncertain purchase outcome. No production demonstration data.
