# Controller and catalog integration verification

The public application entry is `require("bilicomics/controller").new({root, ui})`. `root` is the plugin data directory and `ui` is the current KOReader host. A process-level owner retains the controller across ReaderUI instances and calls `setHostUI`, `setScreens`, `attachReader`, `suspend`, `resume`, and `close`. `services.lua` exports the same constructor for callers using the service-container name.

The controller resolves account directories before opening SQLite or PageStore. Linux sessions retain the data-root path `accounts/<account_key>/session.dat`. Android sessions are stored exclusively under `android.dir/bilicomics/accounts/<account_key>/session.dat`, where `android.dir` comes from Java `Context.getFilesDir()`. Shared DataStorage still holds the account database, immutable chapter descriptors and image cache. Global settings contain only the active account key and public summaries. Startup opens cached account data without network login. Switching accounts terminates and reaps the old worker runner, persists any observed purchase response, recovers unresolved submissions, and then closes the old database. Account generations reject obsolete network and deferred local callbacks.

`session_storage.lua` holds directory descriptors while opening Android account directories with `openat` and `O_NOFOLLOW`. Plugin-created directories must have mode 0700 and the app UID; session files must be regular, singly linked, mode 0600 and owned by the app. Existing `Session.save`/`Session.load` run through kernel `/proc/self/fd` references after those checks; their parsing and serialization are unchanged. A read never adopts an old session from shared storage or creates a credential namespace. A newly validated import is required to establish private storage. Only after a verified private save and successful account switch may the known legacy session for that selected account be removed. Save/open failures preserve the previous account and its legacy file.

All network requests run through the injected runner. The native thread assembles immutable descriptors, commits verified images, merges catalog metadata and owns purchase-journal writes. Purchases require a displayed quote and a fresh worker quote after confirmation. A committed purchase intent precedes the single noncancelable submission worker. Known responses that cannot be saved remain in memory and are retried as local journal completions, never as another charge. Wallet changes do not prove chapter ownership.

`purchase(quote, purpose, callback)` accepts only `read` or `download`, rejects invalid purposes before dispatch, and persists the original action with the purchase intent. The older `purchase(quote, callback)` signature remains a read action. Reconciliation preserves that purpose. Confirmed access never starts reading or downloading by itself: the result dialog offers an explicit continuation for the original `quote.episode_id`. Closing the dialog retires that action; an already-unlocked chapter remains available through ordinary reading and download controls. No automatic continuation queue is created.

The reader opens through KOReader's asynchronous after-open callback. Opening requests own an active-page reference until the native integration takes over; a timeout, superseded callback or failed acquisition cannot retain that reference or complete another request. Saved descriptor identity and local chapter rights are checked before native rendering. Temporary access requires a current process-local online grant and its server expiry. A complete or partial offline cache keeps its original document identity; gaps request sign-in or connectivity without background HTTP when offline.

`lookupComicID(input, callback)` is a separate explicit action from title search. Its bounded parser accepts a positive decimal ID with an optional `mc` prefix and dispatches the existing comic-detail worker. Numeric titles still use title search. `resolveReadingEpisode(comic_id, callback)` loads an unknown catalog asynchronously, resumes an unfinished chapter or selects the next chapter in canonical order. A locked target stays locked and requires an explicit quote.

`setFavorite(comic_id, favorite, callback)` dispatches a noncancelable mutation only after an explicit action. A pending request blocks duplicate clicks. Only a consistent server acknowledgment updates the local favorite; failure never triggers an automatic resubmission. Account generations and per-comic list revisions prevent obsolete account and favorites-list responses from overwriting confirmed state.

`reading_mode` accepts `auto`, `page`, or `strip`; `reading_direction` accepts `ltr` or `rtl`. The reader receives a settings getter, while its integration preserves saved document preferences and reading anchors. Invalid persisted values normalize to `auto` and `ltr`. `getDiagnostics(callback)` uses a separate local worker queue so diagnostics remain available while network work is paused. Its request contains no session, and its result is limited to typed versions, platform and capability fields, normalized defaults, and local session/storage status. A local capability check never claims server verification.

## Tests

`controller_spec.lua` uses real KOReader SQLite, PageStore, Session and PurchaseService implementations. The recorded run passed 66 assertions. A controlled asynchronous runner makes request order, cancellation, stale responses and journal fault injection observable. Nine continuation assertions cover invalid-purpose rejection without worker dispatch, purpose persistence before submission and after unknown-result/account recovery, the compatible read signature, and explicit DownloadService/PageStore completion after access confirmation. Reader handoff is deliberately isolated with an injected opener and small integration stand-in. This suite does not claim to validate the real fork/pipe runner or actual native image rendering; their own suites and `spec/integration/offline_plugin.lua` cover those boundaries.

`catalog_spec.lua` uses the real SQLite/PageStore contract for full favorite synchronization, precise local progress preservation, immutable revision lookup, permissions, retained-download versus automatic-cache state, safe metadata and reopen behavior. The recorded catalog run passed 12 cases.

`authentication_spec.lua` adds 26 assertions with the production Controller, DownloadService, SQLite and PageStore. Controlled worker callbacks establish that image-token and metadata authentication failures pause the account's downloads, retire read-only image/cover work, preserve in-flight purchase responses, and keep cached free/owned content readable. A public invalid-session marker prevents restart or ordinary resume from reusing the rejected private session. Only a newly validated session import creates an enabled service. The suite also covers obsolete account callbacks, assigned cover temporary-file cleanup, cached capacity failures and explicit retry. Existing journal recovery and low-space behavior remain covered by the dedicated jobs suite.

`session_storage_spec.lua` runs 28 additional cases with real SQLite, PageStore and filesystem operations. The Linux run injects an app-private root to exercise the Android policy and verifies unchanged Linux placement. `android_session_plugin.lua` runs the same 28 cases in the unmodified official KOReader APK, API 30 x86, ordinary app UID 10167. It then force-stops/restarts the app and checks 5 more facts in a different PID: private-session loading, no shared-cookie fallback, unchanged cache location and no session-validation request. The Android report records production/test SHA-256 values and actual UID/mode evidence. Sessions and images are synthetic; worker validation is explicitly controlled, so these checks do not claim a real Bilibili login.

`product_features_spec.lua` passes 45 assertions with the real Controller, Catalog and SQLite, using controlled asynchronous worker results. It covers bounded explicit ID lookup, numeric title search, fractional chapter order, Follow acknowledgment and account/list races, reader-default propagation, credential-free diagnostics, output field validation, invalid disk settings and offline queue isolation.

`diagnostics_native_spec.lua` passes 7 assertions with the real fork/pipe Runner, Worker and native UIManager event loop. It obtains local capabilities in a child process while a queued network sentinel remains suspended and unexecuted. The child rejects any diagnostic request containing a session, and controller shutdown reaps its local worker runner. This is a local capability test, not an authenticated Bilibili test.

The Android harness `run_android_session.py` deliberately reuses adb port 5038 and `emulator-5580`. It must run only after the current owner explicitly hands over that app/probe slot; it never provisions another device. After testing, hand the slot to the next owner rather than modifying another task's active probe.

The harness creates synthetic image data, separate XDG directories and account roots. It does not mutate the installed KOReader runtime or global dependencies. Recorded JSON results are kept beside this file. No test imports a real account, requests real chapter images, or charges an account. Authenticated protocol checks and physical device acceptance remain separate release gates.
