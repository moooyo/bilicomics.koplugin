# Native Plugin Integration

All execution is restricted to the authorized remote `test-env` host. No local tests or runtime probes are permitted by the project instructions.

`online_plugin.lua` exercises the actual production entry point, Runtime singleton, Controller, native business views, ReaderUI, Runner process creation and IPC, and SQLite/PageStore. The only substitutes are a documented `Runner.new({worker=...})` dependency and the connectivity result. The worker returns synthetic free/owned/locked catalog data and copies synthetic PNGs to assigned temporary files. It runs in real child processes; PID audit records prove the boundary. No real Bilibili request, account access, quote or purchase occurs.

The online process verifies:

1. Session import and catalog ingestion pass through the actual controller and child boundary.
2. A native chapter opens with a missing-image placeholder before its first acquisition completes.
3. A child-written marker confirms the first worker is blocked at a file gate while independent UI heartbeat callbacks continue; the observed window must keep its largest heartbeat gap below 250 ms.
4. Committing the first image replaces the placeholder with the expected pixels before the chapter is complete.
5. The next image is acquired by prefetch while the reader remains on the first source image.
6. A locked download dispatches no worker, and read/prefetch/download paths never request purchases.
7. Explicit free and already-owned chapter downloads use the same immutable descriptor and reuse in-flight/cache state.
8. Reader closure leaves explicit downloads running; PID audit timestamps prove new image workers start and finish after closure, and both chapters finish and remain pinned.

The test then removes its synthetic session file and starts a separate process using the same data directory. The free and owned chapters reopen offline through the actual controller and ReaderUI, the original source position is restored, actual displayed pixels match the online reference/owned fixture, and the process dispatches zero workers. The separate `offline_plugin.lua` regression is also rerun on a fresh data directory.

The latest frozen snapshot passed 65 assertions: 38 online, 14 offline restart and 13 existing offline smoke assertions. `remote-results.json` includes each result and SHA-256 manifests for the production and test snapshots.

`run_integration.py` creates an immutable production and test snapshot, records its SHA-256 manifest, and executes all three runs. It requires a fresh empty work directory to prevent stale result files or image gates from being reused. It does not modify the official runtime or install global dependencies.

Example after copying the current source tree into a remote staging directory:

```powershell
ssh test-env 'python3 /tmp/plugin-source/spec/integration/run_integration.py --runtime /tmp/bilicomics-native-_duimwe7/lib/koreader --source /tmp/plugin-source --work /tmp/unique-integration-run --fixture /tmp/synthetic-fixtures/page-1.png'
```

The fixture used for the recorded run is a 600 by 2400 PNG with horizontal grayscale bands 40, 100, 160 and 220, generated by the reader suite. Recheck all temporary paths before reuse. The official runtime reports KOReader v2026.07.1 and runs under Xvfb with a 600 by 800 SDL screen.

The results establish cross-layer behavior for synthetic content on Linux x86_64. They do not establish real Bilibili protocol compatibility, real account entitlements, payment success, network transport throughput, physical e-ink refresh quality, or memory limits on Kindle/Kobo/Android devices.
